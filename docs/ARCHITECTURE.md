# Foundation contract (v0.28)
This independent repository supersedes the height-only Tabletop prototype direction, not its existing implementation. Reference: https://github.com/Superior-MI-Labs/Interactive-Tabletop/blob/agent/hex-world-terrain-elevation-and-world-contract-20261125/HEX_WORLD_CONTRACT.md . Retain axial math and fixed 35.264 degree isometric projection with six yaw directions. Unlike the prototype, all ordinary interiors, caves and buildings share Q/R/Z; portals only for intentionally separate spaces.

## Authority
World configuration: smi-hex-world/1. Horizontal nearest-neighbor distance defaults to 5 ft, vertical step defaults to 5 ft, chunk defaults to 16 per axis. Signed integer addresses use floor division. Physical positions are derived, never camera pixels. Immutable grid per world; migration is explicit. A sparse known chunk has a default material and explicit overrides; absence of a chunk means unknown, not air. World.snapshot/restore implements sparse JSON saves (smi-hex-save/1), not streaming or durable indexed storage. Default cells and overrides remain authoritative. The lab exports terrain, placed objects, standalone effects and simulation clock state; visual time and UI state are transient. No gameplay bounds, but JS safe-integer arithmetic constrains representable addresses.

Geometry is a fixed triangulated hex fan: six corners counterclockwise from +30 degrees, center last; triangle i is center, i, (i+1)%6. A cell stores one solid interval between two seven-integer arrays, lower and upper, with 0 <= lower[i] <= upper[i] <= grid.geometry_subdivisions. Supported world profile: exactly 2 subdivisions (0, 2.5, 5 ft at default scale). Pure geometry functions retain parameterized subdivision math for future profiles. Four-slice experimental saves are rejected rather than silently rounded. Full, slab, ramp, peak and excavation are presets, not separate types. Equal lower/upper means zero volume. Multiple disjoint solid intervals and arbitrary geometry within one cell remain future work. Air must have zero solid volume. v0.1 shape kinds are intentionally replaced before persistent worlds exist; no silent migration. The mesh and surface sampler use the same fan. Edge i neighbors axial offsets [0,1],[-1,1],[-1,0],[0,-1],[1,-1],[1,0]; the opposite edge reverses endpoint order. Matching heights can be welded; differing profiles need exposed-face clipping. v0.3 adds explicit atomic connected corner edits (same Z, up to three solid cells; known air skipped, unknown rejected), independent edits, exact horizontal edge interval subtraction, and vertical shared-cap suppression. There is no permanent vertex welding: cliffs are intentionally supported. Unknown neighbors suppress boundary faces until known. The mesh can contain T-junctions; watertight indexed topology is a future gate; GPU depth buffering is implemented. WebGL2 lab previews 19 columns across five vertical levels using depth-tested terrain and alpha-cutout upright sprites. CPU triangle picking uses the same projection and interpolated depth. Canvas overlay is editor guides and debug fire only; no production translucent blending or collision. Presets affect only the selected cell. The subdivision selector is removed. A cell may contain air plus effects; surface state is stored in components.surface and saved with terrain. Excavation clears surface state when volume disappears.

## Time
Host advances simulation explicitly (manual, turn-based, real-time or scaled); frozen ignores advances. Visual animation uses an independent clock, optionally paused by host. Effects: persistent, decorative, timed, reactive. Reactive effects need registered material response rules; no generic automatic fuel/spread in v0.1. Timed effects expire in simulation time, never animation time. Explicit editing remains possible during frozen time. No implicit wall-clock mutation.

## Assets
Atlas owns artwork, pivots, region/sequence/state_set/composition definitions in smi-visual-pack/1. Hex World owns physical placement and state. Providers return validated native pack metadata through a shared resolver, not executable code. v0.4 adds HTTP pack loading, safe relative texture URLs, sprite-subgraph validation, decoded texture size checks and canonical Atlas renderer reuse for region/sequence/state_set. Composition, collection ZIPs, full schema validation, license policy enforcement, cache and integrity verification remain open. Native Atlas renderer is vendored verbatim from a pinned commit; it rasterizes transparent animation frames for GPU billboards. The pinned CC0 tutorial character is a reproducible fixture, not production artwork. Do not claim arbitrary third-party compatibility. A world-specific binding references stable pack/asset IDs and may map physical states to visuals. Prefer world-space surface textures and transparent overlays, anchored vertical sprites, and depth-aware geometry. Use Atlas animation timing rather than a competing format.

## Materials and surface state (v0.5)
The data-only smi-hex-materials/1 catalog defines substrate colors, vegetation compatibility, weighted variants and demonstration burn duration. Physical substrate remains independent of grass, moisture, leaves, snow and scorch. Surface components are validated and persisted. The world ID and address deterministically select a weighted variant. Renderer uses world-space procedural masks for surface coverage and transparent upright grass tuft sprites anchored to exposed triangles. These are debug assets, not published Atlas terrain assets; no parallel animation format. Reactive fire explicitly consumes grass and leaves, reduces health and snow, and increases scorch only when simulation advances. Persistent/timed visual flames remain independent debug overlays and are not saved. Reactive fire state survives terrain export. No fire spread, regrowth, climate model, true translucent blending or chunk mesh caching yet. The sample catalog is a proof of contracts, not a physical simulation. Unknown materials use a diagnostic color.

## Face editing (v0.6)
The depth picker selects the logical face of the hit triangle: upper/lower cap or side edge. A cap exposes seven controls; a side exposes both original upper and lower edge endpoints (four controls), even if clipped by neighbors. The face menu can select hidden faces and coincident handles remain separately accessible through the vertex menu. Overlays are editor controls, not render geometry. The same terrain edit planner supplies limits and atomically clamps all edits, including connected corners, to lower <= upper. Equality is permitted for wedge tips and complete excavation; zero-volume triangles are omitted, and fully collapsed cells become air. No automatic movement of the opposite vertex. This is vertical control editing only, not arbitrary mesh deformation.

## Surface transitions and mesh cache (v0.7)
Derived top-surface attributes share deterministic corner averages across up to three same-Z cells whose exposed triangle edge profiles match at both endpoints. Interpolation from cell centers to shared corners produces continuous material color and snow/leaf/scorch coverage without modifying any stored cell. Unknown, buried and discontinuous edges are excluded. A cliff can receive snow/scorch only within the manifest's upper-rim bleed distance; leaves do not hang from cliff faces. World-space continuous noise and an optional repeating grayscale Atlas region mask break up coverage boundaries. Mask UVs are independent of substrate UVs; cliff rim samples coincide with top-surface coordinates at their boundary. The sample mask is a procedural CC0 fixture, not production art; the canonical Atlas raster path also loads compatible remote region masks. Catalog transition settings define edge strength, mask scale/softness, colors, and bleed depth. Full-strength transitions agree at shared corners; reduced strength deliberately preserves some cell contrast. Coverage debugging visualizes the derived values. Grass sprite density follows interpolated coverage, except non-vegetative substrates. Transitions do not flow between different Z cells, even when isolated endpoints coincide; explicit cross-level surface connectivity remains a future extension. TerrainFaceCache stores derived per-cell meshes keyed by own and neighboring chunk geometry revisions. Surface-only edits reuse mesh topology; geometry/material edits and newly defined chunks invalidate affected caches. This is not streaming or a bounded production cache. Camera supports middle/right drag and pointer-centered zoom. Existing geometry rules and terrain save format are unchanged.

## Art presentation and viewport rendering (v0.8)
A style profile (smi-hex-style/1) binds canonical Atlas static regions to repeating top and side detail and weighted vegetation variants, independent of physical material definitions. One pack session shares image loading across its regions. The fixture uses mipmapped repeating detail, face-normal directional lighting, deterministic barycentric grass placement on slopes, and zoom-dependent stable vegetation subsets. Conservative viewport triangle culling reduces render submission; world storage, simulation and picking remain authoritative. This is not chunk streaming, nor a full terrain LOD system. See [fantasy art direction](ART_DIRECTION.md) for the production quality gate.

## Exploration viewport (v0.9)
The default island remains a small editing regression scene. Explicit exploration mode creates a world with generation.profile=meadow-v1 and a pinned seed. Chunk generation uses signed global lattice corners, shared height samples and the existing two-subdivision volume format. Known chunks are never regenerated; unknown chunks outside the requested region remain unknown. Inverse orthographic projection at both extremes of the five-level demo range determines a conservative axial viewport rectangle and an adjacent-cell halo for geometry/transition dependencies. Pan and zoom request new chunks; the active cell window changes independently of resident authoritative data. A hex ring helper provides exact onion-layer enumeration, but viewport coverage, not forced rings, controls loading. This version generates synchronously and keeps all visited chunks in memory and export saves; it is not eviction, async I/O, infinite storage or terrain mesh LOD. The detailed viewport has a 30,000-cell budget. Mesh cache uses bounded LRU eviction; cell state is unaffected. Reactive fire indexes active world cells rather than the viewport, including restored state, so pan does not pause burns. The exploration profile uses five editable levels only, and supports procedural hills and manual excavation. Cross-Z transition blending is still unsupported. Export before switching world modes; imported exploration saves retain seed and known chunks. Existing island saves continue to work.

## Modular construction and objects (v0.10)
Prefab manifests (smi-hex-prefab/1) are validated relative cell recipes with physical grid compatibility. Rotation uses axial 60-degree transforms and rotates the six corner indices while preserving center and Z. Preview and placement share the same plan; any occupied or unknown cell blocks the entire atomic edit. No special structure mesh or second terrain store: placed geometry remains ordinary editable world cells. First fixtures: gate, platform, step. The lab only permits placement inside its active editable domain. No prefab instance linkage, terrain replacement, support/collision analysis, object recipes or sockets yet.
Placed objects are independent world records with stable ID, cell address, local feet offset, anchor mode and canonical Atlas visual binding. World saves add an optional entities array; older saves without it remain supported. Surface anchors derive height from existing geometry; loss of support leaves an unresolved saved object instead of deleting it. Multiple objects reuse a cached Atlas raster for identical bindings; animation is visual-clock driven. Lab loading is lazy and errors do not remove records. No navigation, physical occupancy, entity picking, movement, collision, persistent standalone effects or production asset-cache bounds yet. The lab includes a tutorial sprite only; artwork remains the v0.8 fixture.

## Prefab capture, saved effects and soft alpha (v0.11)
Capture is an explicit selection of solid cell addresses with the first selection as origin. It exports the existing prefab recipe format; geometry and substrate only, not surface state, entities or effects. Imported recipes use the same validation and atomic placement path. Captured recipes are available for the current browser session and can be exported/imported; they are not a separate world geometry store.
World saves now optionally include placed fire records and simulation clock state. Persistent/decorative/timed effects can coexist across cells; reactive burns retain their existing material-state representation. Timed effects compare against restored simulation seconds, not wall time. Extinguish affects only the selected cell. Expired records remain saved until explicitly removed; standalone effects remain debug overlays, not GPU particles, and only fire is supported currently. Visual clock resets on import. Earlier saves with no clock/effects remain valid.
Optional GPU soft-sprite rendering uses depth-writing opaque cores followed by depth-tested, back-to-front translucent fringes without depth writes. This is an approximate sprite-level sort, not order-independent transparency; intersecting translucent quads may still exhibit ordering artifacts. No production art or shadows added. Existing cutout path remains available as a performance fallback.

## Traversable centerlines and contact shadows (v0.12)
Movement profile smi-hex-movement/1 specifies body height independently of artwork, maximum edge step, maximum grade and bounded search budget. Walk nodes are centered surface anchors, not cell occupancy. Each neighbor step follows two center-to-shared-edge half segments using the same linear terrain triangles as rendering, then a bounded vertical step. Clearance checks all known upper solid intervals across each segment with affine overlap and conservative seam headroom. A zero-thickness ramp boundary is traversable only when backed by a contiguous solid immediately below. Unknown support/clearance is blocked. Breadth-first search minimizes cell steps and returns a route or a diagnostic. Explicit relocation updates the authoritative object only after validation; it is allowed with frozen simulation, like other editing operations. No radius, entity collision, continuous swept physics, animation of movement, jumping, flying, swimming or D&D rules. Nodes are limited by the search budget; same-column vertical movement needs a separate future traversal rule. Route previews are transient and recomputed on actual movement. Contact shadows use existing exposed support triangles, a radial alpha texture, and GPU depth testing; no geometry mutation or separate world data. They are local object shadows, not directional cast shadows, ambient occlusion, or dynamic lighting. Production artwork remains an independent gate.

## Settlement, cutaways and movement presentation (v0.13)
The opt-in settlement-v1 scenario assembles a small stone cottage from ordinary cells and the existing prefab recipe, with one doorway, a shared outdoor/indoor floor, roof and nearby step. Scene identity persists in the world manifest. Cutaway views expose layers at or below a chosen Z and treat known upper cells as visual air only; unknown remains unknown. They generate newly exposed faces through the same terrain pipeline. Physical world queries, saves, collisions and route validation never use the cutaway. The cut can be global or restricted to an explicitly anchored hex-ring footprint. It is not automatic per-building roof fade or fog of war. A bounded line-of-sight query intersects a segment against triangular solid intervals using affine clipping; returns clear, blocked, unknown or budget. Exact grazing along zero-thickness boundaries is not treated as interior intersection. It does not model opacity/material visibility or creatures. Route waypoints drive both preview and playback using the exact center/edge heights from validated walking, including vertical steps; equal-position seam waypoints preserve support ownership for contact shadows. Explicit move commits the final authoritative address immediately; transient playback interpolates the route in visual time at 10 ft/s and may select an optional canonical Atlas walk state. Presentation is cancelled on relevant route geometry revision changes; camera and surface-only refreshes retain it. Saved position remains final. No per-agent simulation, body-radius collision or movement cost rules. Contact shadows follow visual position on the associated support cell. Production art and automated roof detection remain future work.

## Parallel Atlas art integration (v0.14)
Existing smi-hex-style/1 bindings accept a string with default manifest or explicit {manifest,asset} references. Styles loaded from URLs resolve relative manifests against the profile URL. Each load shares pack sessions and static rasters by URL/asset, validates coverage of the active material catalog vegetation IDs, and rejects failed loads without replacing the previous displayed style. RGB detail is an optional multiplicative modulation, not full-color albedo or per-material texture blending. See ART_PRODUCTION.md for agent assignments and qualification. ## Generalized spatial interactions (v0.15)
A validated smi-hex-interactions/1 profile maps enter/leave/use events against cell/entity tags, substrate or normalized surface ranges to named host signals and optional visual contact parameters. Tags persist in existing cell components or entity records; no new spatial store or executable manifest code. moveObject validates route, computes ordered events and optional presentation points, then commits position once. A failed plan emits nothing; preview and frame rendering emit no gameplay events. Events describe each visited support cell and co-addressed entities, excluding the mover, in deterministic order. They are returned to the host as data, not a persistent event journal. Explicit use checks same/adjacent traversable support and targets one cell or object; no remote use. This is cell/centerline contact, not swept collision, arbitrary trigger volumes, continuous physical overlap, door state changes or trap execution. Host owns signal handling and rules. Visual brush response uses interpolated moving poses and world-space distance/height falloff to lean billboard top edges while preserving bottom anchors. Both fixture and Atlas grass use the same response; tagged flexible placed objects can also bend. This is transient visual presentation, not permanent trampling or simulation, and no force is applied to world records. It works with frozen simulation because committed movement is an explicit host action and animation uses visual time. Art LOD does not control event generation. See INTERACTIONS.md for extension/agent handoff.

Interaction profiles can be imported as bounded local JSON in the lab; invalid profiles retain the previous rules. They are session-level host configuration, not saved world state. The direct use check tests only the target step (or standing on the same support), without pathfinding across distant cells. Route geometry revision stamps cancel visual playback conservatively on relevant chunk edits, not on surface/tag changes or view refreshes.

Asset state and animation resolution reuse the canonical Atlas renderer; shared foliage rasters update once per frame at the existing throttled rate. World wind and zones are saved; presentation settings and visual time remain transient. ## Material textures and climate fields (v0.17)
Shared top-surface corner averages now also carry normalized material weights. The renderer resolves each triangle to up to four texture layers (the center and the two corner neighborhoods), collapses unbound materials to the default, and batches by texture set. Each layer samples a continuous world-space repeat; grayscale and RGB detail remain modulation modes, while albedo blends actual RGB with terrain lighting. Cliff/bottom roles bind the owning material and retain rim coverage. No extra transition tiles or saved render weights. Full-color albedo deliberately replaces substrate tint at strength 1; existing snow/leaf overlays remain procedural. Styles may specify detail.materials keyed by physical material, with top/side static Atlas regions and optional color_mode. Texture repeat and strength remain style-wide. Climate is a validated global and spatial override field (season, Celsius, precipitation and intensity), independent of wind. Seasonal vegetation maps optionally replace the existing variant's raster without changing placement, size or density; seasonal overrides inherit procedural wind deformation unless they specify their own wind capability; they can declare independent wind animation states, but do not inherit base artwork state names. No weather simulation, accumulation, temperature gameplay effects, automatic seasonal density changes, or new Atlas format. Fixture texture and seasonal swaps exercise integration only.

## Stable spacing and explicit scatter promotion (v0.23)
Optional family spacing_ft (0–5) opts into shared horizontal neighborhood thinning on the same support level. Candidates are sampled at full LOD from actual known terrain, including a bounded halo around the active domain; deterministic local rank minima reject overlaps without a camera-dependent greedy chain. Hidden candidates reserve their original spacing. Zoom only prunes accepted samples. Plans rebuild on terrain/style changes, not every frame; cutaways only affect presentation. Unknown terrain can change boundary results when it becomes known. Different support levels and non-opted-in families are not mutually spaced; no physical collision or full sprite silhouette guarantee. An explicit editor promotion converts a selected sample to a normal anchored entity using the base Atlas binding, with sampled height/orientation and persistent cell scatter_hidden suppression. Removing/moving the entity does not regenerate its original decoration. Suppression keys are validated and saved with the cell; no separate terrain store. No automatic promotion, undo/restore UI, seasonal behavior transfer, or game-specific logic.

Scatter planning expands only active boundary cells, caps addresses and candidates at 60,000 each, and reports an explicit budget failure instead of rendering a partially thinned set. The editor lists only samples at the current LOD. Browser qualification includes save/delete behavior after promotion.

## Explicit object collision (v0.24)
An entity may declare a host-owned vertical cylinder (collider:{kind:"cylinder",radius_ft,height_ft}), independent of Atlas pixel dimensions and orientation. A resolved anchor supplies its base position; unresolved support creates no active collider. Existing entities remain nonblocking by default. Route planning builds a bounded snapshot of active volumes once per query and checks the swept horizontal disk and vertical interval along the same center/edge/rise segments used for walking and playback. Optional movement radius_ft defaults to zero and applies only to object collision, not terrain clearance (still centerline). Actor IDs are excluded from their own query; explicit use excludes its target but not other obstacles. Collider edits persist and bump a conservative collision revision for presentation invalidation. The editor can apply/remove a collider and show its volume. This is a first collision primitive, not rigid-body physics, placement rejection, terrain radius clearance, projectile collision, dynamic door blockers, or automatic colliders from artwork. Queries over 4096 active blockers reject explicitly; a spatial index is future work.

## Indexed queries and conditional blockers (v0.25)
Collision queries now build a transient uniform 16-ft XY bucket index from resolved active cylinders, with vertical interval pruning and exact swept narrow phase. All intersected buckets receive each cylinder; long queries conservatively fall back to exhaustive checks. Bounds are explicit (65,536 active volumes, 256 query buckets before fallback); no additional persistent spatial authority. The optional host collider.disabled_when:{input,equals} condition disables a cylinder when the explicitly materialized visual input matches. The existing Atlas slot/preset resolver supplies the effective input on editor apply and authored use; the world rejects missing or wrong-type condition inputs and commits the appearance/collider atomically. No arbitrary manifest grants physical authority. The same input drives visual and physical state; revisions change only when active status or collider geometry changes. The browser pilot uses the chest fixture as a technical toggle, not realistic chest physics. Closing a blocker around an occupied position is not automatically rejected; terrain-radius clearance, rigid-body dynamics and multi-shape colliders remain future work. Old saves and unconditional colliders remain valid.

## World lighting and environmental shading (v0.26)
The existing style.lighting contract gains bounded occlusion, sprite_strength and shadow_strength factors; optional world.environment.lighting overrides style lighting and survives saves. Old saves/styles remain valid. Terrain ambient occlusion is derived from six nearby solid-volume probes above shared top vertices using actual known terrain, cached per decoration rebuild. Unknown space contributes no visual occlusion; cutaway does not alter the real light probes. Lighting is applied after material and cover blending, so snow and leaf overlays are shaded too. Sprite tint is a camera-independent approximate ambient response, not a normal map. ## Local colored lighting (v0.27)

## Authored water surfaces (v0.28)
Optional cell.components.water stores a fill fraction (0–1 of cell height) and world XY flow_ft_s (magnitude <=30). This is a prescribed fill plane in the void of the existing solid fan, not a replacement material, conserved volume solver or second terrain store. Horizontal triangles clip against both solid planes, with local depth measured above the upper surface or cell floor. Full-cell interfaces are suppressed beneath continued water, contacting solid ceilings, and unknown upper cells. Derived water faces rebuild with terrain edits and cutaway views; geometry presets preserve water when removing solids. The existing WebGL renderer uses a depth-tested, back-to-front translucent surface pass with world-space procedural ripples and prescribed flow, depth coloration, sun and local light. No simulation time advances from presentation. Water currently renders only horizontal free surfaces, without vertical faces, reflections, transmission, pressure, buoyancy, swimming, fire extinguishing or intercell fluid transfer. Transparent sprite fringes and water use approximate separate pass ordering. The editor can fill/drain a cell and set flow; saves round-trip the validated component. Atlas format unchanged; future art profiles may bind water detail textures through existing asset loading.
