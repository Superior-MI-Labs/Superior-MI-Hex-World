# Hex World application workspace — Batch A
Preserve the authoritative world, Atlas, editor history and plan contracts. The desktop shell organizes the original control IDs into a fixed-height viewport, inspector with section navigation, tool icon rail, compact file/history actions and status bar. The icon rail selects the existing brush control, not parallel tool state. All original controls remain reachable; diagnostics are in the inspector. Collapsing the inspector and focus mode enlarge the world without modifying it. Narrow windows place the inspector below the viewport.

Viewport resizing observes the container; both canvases share one bounded pixel size (no DPR multiplier, 1600×1000 and 1.2M pixels maximum). Projection, picking and overlays use backing coordinates, and the center world point is preserved on resize. Zoom remains in backing pixels per foot; resolution caps may affect apparent scale on very large displays. Resize is deferred during pointer gestures. Larger visible areas require real hardware profiling.

This batch deliberately preserves existing inspector controls and groups. Next: contextual inspector, visual Atlas thumbnails and palette, scene hierarchy, reviewed placement. Do not add a second command or catalog. Production art and archive retention remain separate gates. Qualification includes existing browser workflow, responsive dimensions, icon-tool mapping, panel toggles and live Atlas round-trip.

## Batch B/C: contextual inspector and first visual library slice
One inspector section is visible at a time. The toolbar still selects the existing paint control; primary brush fields are filtered by the actual tool, with all settings recoverable via the All brush settings button or procedural tools. No new world state. The catalog view uses the existing filtered matches and selected asset ID, shows at most 24 cards per page, and uses only Atlas's same-origin digest-addressed preview path. Missing or invalid previews receive an explicit fallback. The existing load button still performs runtime qualification, rather than trusting the thumbnail. Atlas's authored tags, subjects, aliases and style participate in search. Tests navigate visible inspector tabs; core assertions remain unchanged. The bottom dock, scene hierarchy, drag/drop and free placement remain future slices. No production art or target-device performance claim.

## Batch C/D: collapsible asset dock and scene hierarchy
The Atlas browser and pinned palette now occupy a single optional bottom dock; the same original controls are relocated, not cloned. Closing it returns screen space to the viewport, and focus mode hides it without changing the world. The object inspector retains placement, appearance, physics and lights; low-level binding fields are advanced. The scene hierarchy is a paginated read-only projection of existing persistent entities, searchable by asset/ID/address and grouped by level. It selects through the existing cell and object inspector path; focus centers the selected support, optionally loading the active exploration region, and refuses hidden cutaway targets. New object placement selects the new ID through the same inspector. No scene graph, new persistence format, or object-picking approximation. Direct viewport sprite picking requires reliable depth/alpha handling and remains a later slice. Qualification is pending; the previous B/C run is not superseded.
